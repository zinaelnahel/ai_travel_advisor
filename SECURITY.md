# Security review

Reviewed the stateless FastAPI application, notebook interface, API transport, tool dispatch, summaries, images and benchmark workflow. This is a demo with optional password authentication, not a hardened public service. Trip state is signed, not encrypted, and held by the browser. Signatures prevent modification but do not prevent replay; budgets are not account-wide spending limits.

| Risk | Implemented mitigation | Remaining limitation / production next step |
|---|---|---|
| Prompt injection in messages or external results | System instructions label external content, summaries and tool arguments as untrusted. Tools are selected from a fixed allowlist; no shell, filesystem, payments or booking tool exists. | Prompts cannot guarantee scope or factual correctness. Add adversarial evaluations, abuse detection and a separate policy layer before public deployment. |
| Malicious tool arguments / SSRF | Exact argument keys and server-side type, length, ASCII currency and finite-number checks. Fixed HTTPS hosts, URL-encoded city queries, no redirects. No model-provided URL is fetched. | DNS/network compromise remains outside this application. Enforce network egress restrictions in production. |
| Secret disclosure | Key stays in the Python runtime and Authorization header to OpenAI only. Provider error bodies are not displayed. .env is ignored by Git. | Notebook/kernel access exposes runtime secrets. Do not share an executed notebook or logs containing personal chats; clear outputs before sharing. Rotate any previously committed key; Git ignore does not remove tracked secrets. |
| Unsafe notebook rendering | Markdown is HTML-escaped before conversion and sanitized with Bleach; remote image tags, scripts and executable URL schemes are removed. Generated images are bounded PNG bytes, never fetched from model-provided URLs. | HTTP/HTTPS links can still lead to untrusted sites; review destinations before opening links. |
| Runaway spend / denial of service | Input size, output token, context, response byte, tool-step and tool-count limits. Estimated per-conversation budget checked before calls; one bounded budget-repair attempt and no automatic HTTP retries. UI disables action controls during requests. | Estimates and missing usage prevent a hard billing guarantee. New trip resets the local budget. Configure project-level spend limits/rate limits; authenticate users for public use. |
| Summary loses constraints or launders injection | Low-cost factual summary preserves corrections, conflicts, dates and constraints. Recent complete turns retained when small; old text batched under conservative context bounds. Summaries remain user-role data, never system instructions. Commit only after successful summaries. | Summaries are lossy; require user review of assumptions and test long conversations with contradictory constraints. |
| Hallucinated live facts / inappropriate scope | Weather and rate questions use tools; source URLs, units and dates are provided. Seven-day forecast limitation and reference-rate caveat enforced in prompts. Travel scope and no-booking rules. | The model may misinterpret results or ignore prompt rules. No current transport schedules or booking inventory source exists; these must remain estimates. |
| Privacy / image prompts | Image generation receives only destination, duration and interests, not the full personal transcript. | Users can still place sensitive data in those fields. OpenAI receives chat/summary data; weather service receives the city and currency service receives the source currency. Explain provider retention settings before deployment. |

Regression tests cover hostile arguments, unapproved hosts, unsafe rendering, generation handoff, tool failures, failed-turn accounting, budget/context limits, summary failure recovery and image failure behavior. These are code-level controls; passing tests does not prove immunity to prompt injection.

The dependency ranges are constrained, but this review did not perform a dependency vulnerability scan or a penetration test. Production use also needs TLS termination, authenticated access, per-user isolation, rate limiting, secure secret storage and reviewed retention/logging policies.
